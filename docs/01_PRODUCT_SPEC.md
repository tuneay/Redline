# Product Specification

## Working name

**Redline**

Tagline:

> Pressure-test the idea before you build it.

The name represents a critical threshold: the line beyond which an idea's assumptions no longer survive scrutiny.

## Product category

AI idea interrogation and founder reasoning tool.

Redline is not:

- a generic chatbot;
- a startup idea generator;
- a motivational founder coach;
- a market-research engine;
- an investor simulator;
- a business-plan writer;
- a score generator with decorative numbers.

## Core user

A builder, founder, developer, designer, or student who has a project idea but has not yet proven:

- who urgently needs it;
- what behavior must change;
- why existing alternatives are insufficient;
- how the first users will be reached;
- which assumption can kill the idea.

## Job to be done

When I am excited about a project idea, help me expose the parts I am rationalizing before I spend days or months building it.

## Core transformation

```text
Unstructured enthusiasm
→ explicit assumptions
→ pressure-tested contradictions
→ a decision
→ a real-world validation action
```

## Product principles

### 1. Directness over encouragement

The user does not need applause for describing an idea. The system should identify what is unsupported and why it matters.

### 2. Evidence over theater

A severe tone without evidence is merely performance. Every important criticism must trace back to:

- a user statement;
- a contradiction between statements;
- a missing answer;
- an explicit unknown;
- a basic product reasoning principle.

### 3. Questions over premature conclusions

The system asks five adaptive questions before delivering a verdict. It should not decide after the opening description.

### 4. Action over diagnosis

The final output must include a validation order that can falsify the idea. “Do more research” is not an acceptable action.

### 5. Precision over comprehensiveness

The MVP does not need every business framework. It needs to identify the single most dangerous failure path.

## Desired emotional experience

The user should feel:

- understood rather than flattered;
- challenged rather than attacked;
- slightly uncomfortable because vague claims are exposed;
- clearer about what must be proven;
- relieved that the next action is smaller than building the full product.

The user should not feel:

- mocked;
- manipulated;
- trapped by endless questions;
- overwhelmed by a consultant-style report;
- deceived by false market claims.

## Primary success moment

The user reads a sentence in the final verdict and thinks:

> “That is exactly the part I was avoiding.”

## MVP output

The verdict includes:

- verdict label;
- survival score and confidence level;
- one-sentence diagnosis;
- strongest signal;
- critical failure;
- detected contradiction or avoidance pattern;
- assumptions classified by risk;
- reconstructed idea;
- immediate validation order;
- explicit do-not-build list;
- evidence references to the user's answers.

## Verdict labels

### BUILD

The problem, user, behavior, and first distribution path are sufficiently concrete to justify a narrow build. This is not proof of business viability.

### VALIDATE

The idea is coherent, but one or two fatal assumptions remain untested. The next step is an experiment, not a product build.

### RESHAPE

A real problem may exist, but the current user, solution, positioning, or business logic is misaligned.

### KILL

The user's own answers indicate no urgent problem, no reachable user, no behavior change, or a contradiction that destroys the current concept. `KILL` applies to the current formulation, not to the user's ability.

## Heuristic score

The score is a structured reasoning aid, not an objective valuation. It must always include a confidence level:

- low confidence;
- medium confidence;
- high confidence.

Low-information answers produce lower confidence, not invented precision.

## Language behavior

The interface and AI mirror the language used by the user. Mixed-language conversations should preserve the dominant language. Internal schema keys remain English.
