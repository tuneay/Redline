# Post-MVP Roadmap

Nothing in this file belongs in the first implementation unless the MVP is complete and validated.

## Validation signals before expansion

Look for:

- users completing all five questions;
- users copying or saving verdicts;
- users revising an idea and repeating the flow;
- screenshots or quotes shared voluntarily;
- users saying the system identified something they were avoiding;
- users acting on the validation order;
- repeated demand for project history.

Do not prioritize vanity metrics such as time on page without understanding whether users were confused.

## Stage 1 — Revision loop

Allow a user to revise the idea after a verdict and run a second interrogation.

Output:

- score movement;
- assumption changes;
- contradictions resolved;
- remaining fatal risk.

This is the strongest next feature because it turns a one-time experience into a reasoning loop.

## Stage 2 — Local idea history

Keep multiple local sessions without accounts.

- named ideas;
- previous verdicts;
- compare revisions;
- export all data.

Only add cloud persistence when cross-device demand is real.

## Stage 3 — Evidence mode

Let users attach structured evidence:

- interview notes;
- commitments;
- payments;
- usage observations;
- experiment results.

The AI should distinguish stronger evidence from opinion.

## Stage 4 — Market verification

Add optional web research as a separate mode, not silently.

It should:

- identify current alternatives;
- verify factual market claims;
- cite sources;
- distinguish research from user-reported evidence;
- show retrieval date.

Do not let web search dilute the five-question core.

## Stage 5 — Founder pattern memory

Across multiple ideas, detect recurring reasoning patterns:

- repeatedly avoiding distribution;
- overbuilding before validation;
- confusing users and buyers;
- relying on AI as differentiation;
- choosing infrequent problems for subscriptions.

This can become Redline's durable product value.

## Stage 6 — Voice interrogation

A real-time spoken session can increase pressure and reduce over-edited answers.

Requirements before building:

- excellent interruption handling;
- transcript review;
- privacy controls;
- no fake emotional manipulation;
- clear recording state.

## Stage 7 — Team conflict mode

Co-founders answer independently. Redline reveals where assumptions differ.

Potential outputs:

- user-definition disagreement;
- different success criteria;
- conflicting revenue expectations;
- unspoken execution ownership.

## Stage 8 — Public verdict

Shareable hosted reports may drive growth, but only with explicit consent and redaction controls.

Never publish a conversation by default.

## Possible business model

- free single verdict;
- paid revision history;
- evidence-backed reports;
- founder pattern analysis;
- team sessions;
- private workspace.

Do not add payments before the result is valuable enough that users ask to preserve or repeat it.

## Long-term positioning

Redline should evolve from:

> harsh idea chatbot

into:

> a reasoning system that tracks which assumptions a founder repeatedly avoids and which evidence changes a decision.
